# 月隐镇 · 狼人杀

面向线下聚会的 12 人狼人杀助手：法官控制台、手机玩家页面、法官代操作、服务端身份隔离、独立持久化目录。

## 本地运行

需要 Node.js 22+。

```bash
npm ci
npm test
npm run build
npm start
```

默认监听 `127.0.0.1:3201`。浏览器打开该地址进入自动分配身份的演示房间。右上角 `+` 可创建真实房间；复制房间号旁的邀请按钮，将链接发给玩家。开发时可同时运行 `npm start` 和 `npm run dev`（Vite 转发 `/api`）。

局域网试玩：`HOST=0.0.0.0 npm start`，用电脑的局域网 IP 访问；手机需要在同一网络。HTTP 环境若不能访问剪贴板，会弹出可手动复制的邀请链接。

## 第一版范围

4 狼人、预言家、女巫、猎人、白痴、4 平民；夜间行动、天亮发言、放逐投票、自动胜负判定。狼人行动最高票生效，平票空刀；放逐平票无人出局；无警长和 PK。女巫每夜最多一瓶药，仅首夜可自救；被毒猎人不能开枪；白痴首次被投翻牌免死且失去投票权。获胜条件为好人消灭所有狼，或狼清空平民/神职之一。

房间状态每 1.5 秒同步。玩家凭证仅保存本机浏览器，勿清除浏览器存储；该版本没有换设备身份找回和法官转让功能。房间号用于加入，不是访问密码。法官预览只显示所选玩家允许查看的信息；真实玩家不能访问法官接口。

## 数据与部署边界

单 Node 进程，无 Docker、Redis、独立数据库依赖。`DATA_DIR` 默认为 checkout 同级的 `games-data`，不是代码或构建目录。生产应显式设为 `/var/lib/games`。状态包含私密身份与访问凭证，目录与文件分别以 0700/0600 创建，应由独立服务用户拥有。`PORT` 默认 3201，`HOST` 默认 127.0.0.1。不要运行多个写入同一数据文件的进程。

尚未部署到用户服务器。拟定目录为 `/opt/games/releases/<SHA>`、`/opt/games/current`、`/etc/games`、`/var/lib/games`；拟定应用端口 3201，Nginx 公网端口 8081，正式操作前须复查占用。不得修改 `/opt/photo`、`nature-photo` 或已有 Nginx 站点，也须避开 story-writing 的 3101/8443。生产建议在开发环境构建，将产物上传小内存服务器。

本版适合原型体验；公开部署前需按最终访问方式配置独立 HTTPS/访问认证、请求限流、备份和房间清理策略。当前内置 200 房间上限、请求体大小限制、同源写入检查，不提供互联网级反滥用保障。

## 服务器发布

发布前在开发环境运行 `npm ci`、`npm test`、`npm run release`，将 `deploy/web` 和 `deploy/artifacts.sha256` 与源码一起提交。服务器直接使用这些预构建文件，不运行 npm 安装或构建；运行时只需要现有 Node.js 22+。

`deploy/manage.sh` 支持首次 `install`、后续 `update` 和 `rollback`。安装和更新需要传入本次下载源码目录及完整提交 SHA；聊天中会提供包含真实 SHA 和归档校验和的完整命令，不追踪浮动分支。

首次安装先检查资源、Nginx、自然图鉴状态、3201/8081 端口及路径冲突；有冲突立即退出，不复用或覆盖。使用独立 `moonveil-games` 系统账号和 `moonveil-games.service`。仅新增 `/etc/nginx/conf.d/moonveil-games.conf`，通过配置检查后平滑 reload Nginx。不会停止或重启 `nature-photo`，也不修改 `/opt/photo` 或 story-writing。安装过程结束还会核对自然图鉴的服务状态与 PID。

访问地址为 `https://123.57.60.66:8081`。独立自签名证书和私钥保存在 `/etc/games/tls`，访问用户名为 `games`，密码仅在服务器交互式终端输入，保存 SHA-512 crypt 哈希到 `/etc/games/htpasswd`。所有玩家共用站点访问密码，但每个玩家的游戏凭证独立。游戏凭证使用 `X-Moonveil-Token`，与 Nginx Basic 认证不冲突。自签名证书会引发浏览器证书提示；只在确认访问的是本人服务器时继续。

`/etc/games/environment` 与 `/var/lib/games` 独立于版本目录。更新不改这些目录的权限或内容，不更新证书和密码。旧版本不会删除；切换前在 `/var/backups/moonveil-games` 保存当前房间文件快照。使用原子符号链接切换代码，只重启 `moonveil-games`，检查真实运行版本、服务状态与 HTTPS 认证保护。任一步失败即停止，不显示成功，不自动继续重启。初次安装失败会清理本次新增的 Nginx 站点并停用本次新增游戏服务；保留数据与配置供排查。

后续更新若已经切换而验证失败，可以执行 `sudo bash /opt/games/current/deploy/manage.sh rollback` 回到上一代码版本。回滚同样保留当前业务数据，不自动恢复快照；未来若有不兼容数据迁移，需要另行设计迁移/恢复流程。首次安装没有上一版本可回滚。

仅需在阿里云安全组放行 TCP 8081；3201 保持本机监听，无需对公网开放。部署脚本不修改安全组、UFW、现有服务和系统 Node 安装。若存在额外系统防火墙拦截，应先只读检查后再单独处理。

## 玩家积分与荣誉榜

导航栏「排行榜」展示跨房间累计积分，以及狼王、神眼预言家、灵药女巫、神枪猎人、不屈白痴、平民之光。每局参赛 3 分，阵营胜利另加 7 分；无存活奖励。个人表现合计限制在 −3 至 +3 分：好人投中狼人 +1，预言家首次查中每位狼人 +1，女巫解药 +1，毒药或猎人枪击狼人 +2、好人 −2。弃票、空刀和放弃技能不加减分；狼人依靠阵营胜利得分。代操作同规则。

总榜按积分、胜率、胜场依次排序，完全相同并列。每个角色奖要求该角色完成至少 3 局且至少 1 胜，按该角色胜场、胜率评选，允许并列；荣誉不额外加分。

仅新版本开始且由 12 个独立玩家档案参与的真实完整对局计分。演示、补入演示玩家、未结束和旧版对局不计分。结束页显示本局每人的得分组成，服务端在结束时保存一次结算；积分和档案标识随 `DATA_DIR/rooms.json` 持久化，重启不丢失。不要删除已结算房间文件，否则累计记录也会丢失；现有 200 房间限制仍适用。

玩家首次加入会在浏览器保存随机档案凭证（`moonveil-profile-v1`），之后在同一浏览器跨房间自动累计。同名不合并，清除存储或换浏览器会形成新档案，暂不支持恢复或转移；昵称使用档案首个计分记录的名字。不要分享浏览器凭证。同一档案不能在同房间重复入座。公开榜单仅返回昵称、短档案编号和结束后的统计，不包含登录凭证或进行中身份。此机制适用于朋友聚会，不提供账号级防刷分。


## 同房间多局与榜单范围

一局结束后，法官可点击「同房间，再来一局」，确认后回到准备阶段，再点击分配身份开始下一局。房间号、玩家座位、房间凭证及浏览器档案保持不变；所有玩家复活，身份重新随机分配，药水、查验、行动和日志重置。进行中的对局不能重开。旧版已结束房间也可使用该入口继续下一局。

排行榜支持「历史总榜」（全部房间累计）与「本房间榜」（当前房间历次对局累计）。两种范围使用相同计分和荣誉规则；房间榜需要当前房间凭证。已结算的积分保存在房间历史中，重开和服务重启不会清空或重复计分。演示局、含演示玩家的房间仍不计分。保留 `DATA_DIR/rooms.json`，其中包括历史积分；不要删除已完成房间。
